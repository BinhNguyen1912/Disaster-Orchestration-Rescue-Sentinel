🔐 Bảo mật flow Quên mật khẩu (OTP + resetToken)

User gửi request → Server tạo OTP (6 số, 5 phút) + resetToken (UUID) → Lưu DB → Gửi email cho user ↓ User gửi: resetToken + OTP + newPassword ↓ Server verify 3 điều kiện → Update password → Xóa OTP/resetToken
Yếu tốMục đích
resetTokenLà "key" — user truyền trong request reset password, không gửi qua email
OTPLà "password" — gửi qua email/SMS, attacker không biết nếu không có quyền truy cập hòm thư
resetToken: UUID v4 ngẫu nhiên (~122 bit entropy, không đoán được). Dùng 1 lần — sau reset thành công, cả OTP và resetToken đều bị xóa khỏi DB.
